# Qwen High指摘の後続対応（2026-09-25）

## 実装順と採用条件

1. H-2: 記事表示時のOGP再生成を予約処理へ移し、記事表示中に画像を描画しない。重複予約、保存後の再確認をテストする。
2. H-6: ZIPを検証して別ディレクトリへ配置し、旧テーマを退避してから切り替える。切り替え失敗時の復元と旧ファイルの除去をテストする。
3. H-10: 管理画面の全量取得と初期化時の再索引を、現行データ件数と実行条件で評価する。十分な負荷が確認できる経路だけ別タスクで修正する。
4. H-11: 検索時の本文REGEXPを計測し、現行規模での影響を判断する。索引移行は検索結果の一致と既存記事のバックフィル手順が揃ってから実装する。

## Preview 6への反映結果

- H-1: Geminiモデル一覧の同期は最大3ページ、各リクエスト10秒に制限し、同期処理の待ち時間を抑えた。
- H-2: 古いOGP画像の再生成を30秒後の単発Cronへ移し、記事表示のリクエスト中に描画しない。
- H-3: ブログカードとNode LibraryのOGP取得からTLS検証無効化を削除した。証明書検証エラーは取得失敗として扱う。
- H-4: Previewの記事要約は `template-parts/single/hero.php` が表示し、指摘された色上書き経路はなかったため変更対象外。
- H-5: 要約とファクトチェックAJAXで対象投稿の `edit_post` 権限を確認。別投稿の編集権限がないユーザーの拒否をAJAXグループテストで確認。
- H-6: 更新ZIPの検証後に新テーマを準備し、切り替え失敗時の旧テーマ復元と古いファイルの除去を実装。回帰テストで検証。
- H-10/H-11: 下記の実測では今回の最適化を正当化できず、全件制限や検索索引移行は保留。

H-7のサイズ判断はテーマZIPと独立プラグインZIPを分けて確認する。Qwenレポートの `73.7KB + 51.7KB = 327.1KBの約7割` は算術上誤りで、合計125.4KBは327.1KBの約38.3%。この比率だけでは変更を採用しない。H-8は現行ビルド計測が必要、H-9の分割取得と検索データ移行、CSS整理・ファイル分割も互換性評価を別途行う。

## LocalWPの読み取り専用計測

`cybernode.local` のDBで、公開Library 35件、公開記事39件、シリーズ7件を確認した。Library一覧取得は8回の中央値が1.65ms、画像条件の本文REGEXPは8.93msだった。REGEXPの `EXPLAIN` は `type_status_date` を使い、39件を候補として本文条件を評価していた。これはLocalWPでの短い単独クエリ計測であり、管理画面全体の描画時間や本番負荷を示すものではない。

Libraryカード参照の索引バージョンは現行の `3` と一致し、全件再索引は通常リクエストでは実行されない。予約投稿チェックも5分のtransientロックで抑制されている。これらのコード上の全量取得は残すが、今回のデータ規模では件数制限による項目欠落や検索索引移行の互換性リスクが、測定できた負荷改善より大きい。

## 次に再判断する条件

- Library・シリーズ・記事件数が大きく増えたとき、または投稿編集画面や検索の実測遅延が報告されたときに、クエリごとの回数と時間を再計測する。
- H-11を再開する場合は、メディア種別ごとの現在の検索結果IDを保存し、保存時索引と既存記事の分割バックフィルを設計する。移行中は旧検索との結果差を比較し、全件一致が確認されるまで旧経路を削除しない。
- H-6の配布前には、同一版ビルド更新、更新失敗時の復元、配布ZIPのルートとビルドIDを実環境でも確認する。
