# アーカイブ・検索結果の並び替え案（N29 / N38 / N14）

検索結果とアーカイブに共通して「古い順」「新しい順」の2択を表示し、既定を古い順にする。検索条件・カテゴリ等は切替時と追加読込時に維持する。

## 案A: 結果一覧の直上に常時表示（推奨）

見出し・件数の近く、カード一覧の前に同じラベル付きセレクトを置く。検索結果の既存の詳細設定内の並び順は移し、同一ページで二重に出さない。どちらの画面でも選択肢が見つけやすく、モバイルでは幅に応じて折り返す。

## 案B: 検索・絞り込みの設定内

検索結果は現行の詳細設定内を使い、アーカイブにも設定の開閉領域を設ける。一覧がすっきりする一方、並び替えが隠れる。

## 案C: 独立したツールバー

結果件数や将来の絞り込みとともに共通ツールバーへまとめる。拡張しやすい一方、今回の2択だけには構成変更が大きい。

## 実装時に必要な検証

同じ日付の記事はIDを第2キーとして固定し、1ページ目とREST追加分のクエリ、選択方向、検索条件、カテゴリ等を一致させる。重複排除はDOM上の実際の記事識別子を用い、読み込みエラー時はページ送りまたは再試行へ復帰させる。投稿の追加・更新がページ取得途中に発生する場合の重複・欠落対策も検討する。最終ページで監視とスピナーを終了し、フッターへ到達できることを確認する。
